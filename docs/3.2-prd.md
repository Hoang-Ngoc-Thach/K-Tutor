# 3.2 — PRD (Product Requirements Document)

**Status:** Accepted (amended — see revision note)

> **Revision note:** After the initial acceptance of this PRD, UI implementation surfaced three scope questions (an AI chat-style feature, a vocabulary mini-game, and a topic-based content structure). These were resolved with the team and are reflected below as FR-11 through FR-13, plus a clarification to the chatbot non-goal. This is a deliberate, reviewed amendment, not a silent addition.

## Goal

Help Korean learners follow a vocabulary/grammar path suited to their goal (conversation or TOPIK), practice reading using text they scan themselves, check their own written sentences, and review vocabulary — all with AI assistance.

## Users

- **Conversation learner:** needs practical, everyday Korean, organized by topic.
- **TOPIK learner:** needs exam-oriented vocabulary/grammar (level not differentiated in v1).
- **Website administrator:** manages content and users, and reviews usage statistics; not a language learner in this role. Uses the same login screen as learners — access level is determined by role after authentication, not by a separate login flow.

Learner roles share the same account model and interface; the only difference is which learning path content is shown. Admin is a distinct role with a separate dashboard, not a variant of the learning path.

## Functional requirements

1. A user can register with a valid email and password, then log in with those credentials.
2. Invalid registration and login requests show a clear error without exposing sensitive authentication detail or discarding safe form values.
3. On first login, a user selects a learning goal: conversation or TOPIK. This selection determines which learning path they see and can be changed later from account settings.
4. A user can view and progress through a vocabulary/grammar learning path matching their selected goal, item by item.
5. A user can mark a vocabulary/grammar item as learned or not yet learned; this state persists across sessions.
6. A user can upload or capture an image containing Korean text (handwritten or printed).
7. The system extracts editable text from that image (OCR) and displays it for reading practice.
8. A user can trigger AI text-to-speech playback of the extracted text, using a default AI voice.
9. A user can view a summary of their own progress: items learned, items remaining, in their selected path.
10. All user-facing interface text is in Vietnamese.
11. **(New)** For the conversation goal, the learning path is organized into named topics (e.g. "Chào hỏi & Giới thiệu"); a user can browse topics and see their own progress per topic.
12. **(New)** A user can submit a single Korean sentence they wrote, and receive AI feedback: confirmation if correct, or an explanation and corrected version if incorrect. This is a bounded, single-turn exercise — the system does not maintain a multi-turn conversational context between submissions.
13. **(New)** For a topic the user has studied, they can enter a review mode with at least three quiz formats: typing the Vietnamese meaning of a shown Korean word, typing the Korean word for a shown Vietnamese meaning, and matching pairs of Korean words to their meanings.
14. **(New)** A user account has a role: learner or admin. Login uses the same form for both; after successful login, the app routes learners to the learning path and admins to an admin dashboard.
15. **(New)** An admin can create, edit, and delete vocabulary/grammar items, and organize them into topics used by the conversation learning path.
16. **(New)** An admin can view a list of registered users and can lock or unlock a user's account (locking prevents that user from logging in).
17. **(New)** An admin can view usage statistics: at minimum, total registered users (broken down by goal — conversation vs. TOPIK), and the most-studied topics.

## Non-goals

No voice cloning (reading text back in the user's own voice), no automatic pronunciation scoring, no TOPIK content above level 4, no mobile client, no password reset, email verification, SSO, or social login in this release.

**On chatbot scope (clarified):** an open-ended, multi-turn, free-form conversational chatbot remains a non-goal. FR-12 (AI sentence feedback) is explicitly not this: each submission is independent, bounded to one sentence in and one piece of feedback out, with no requirement that the AI retain context across submissions. If a future version blurs this line (e.g. by adding conversational memory), that is a new scope decision requiring its own review, not an extension of FR-12.

**On the Hangeul-matching mini-game:** not a functional requirement in v1. It may exist as static, non-interactive homepage decoration; it is not connected to real vocabulary data or a scoring/XP system in this release.

**On admin scope:** a single flat "admin" role only — no multi-level roles (e.g. super-admin vs. moderator), no admin action audit log, and no admin self-registration flow in v1 (admin accounts are set directly, not created through a public sign-up form).

## Assumptions

- A single account has only one active learning goal at a time; a user does not study both goals simultaneously.
- Learning path content (the actual vocabulary/grammar items) will come from a data source that is not yet selected — see `3.1-product-discovery.md` — and is treated as available once the technical decision is made.
- AI sentence feedback (FR-12) will be powered by the Google Gemini API (free tier), pending final confirmation in the Chapter 5 architecture decision.
- The "forgot password" link may appear in the UI for visual completeness but has no backend logic in v1, consistent with the password-reset non-goal.
- Each user record has a role attribute (learner or admin); admin roles are assigned directly (e.g. via database/seed), not through any UI flow, since the admins are the team members themselves.

## Non-functional expectations

- Interface fully in Vietnamese, including error messages.
- OCR and TTS are v1's primary technical risks; a clear failure state with retry is required even if underlying accuracy is imperfect.
- Web-only in v1; do not design against anything that would block a future mobile client, but do not build mobile-specific work now.

## Acceptance signal

Learner path: register → log in → select goal → browse a topic and progress through learning path items → scan a text image → review extracted text → play AI reading → write a sentence and receive AI feedback → review a topic's vocabulary via quiz → check progress summary → reload and confirm state persists.

Admin path: log in with an admin account (same login form) → land on admin dashboard → create/edit a vocabulary item within a topic → view the user list and lock/unlock an account → view basic usage statistics.

See `3.4-user-stories-acceptance-criteria.md` for detailed user stories, and `3.5-feature-specification.md` for detailed technical behavior.
