# 3.2 — PRD (Product Requirements Document)

**Status:** Accepted

## Goal

Help Korean learners follow a vocabulary/grammar path suited to their goal (conversation or TOPIK), and practice reading using text they scan themselves, with AI reading it back aloud.

## Users

- **Conversation learner:** needs practical, everyday Korean.
- **TOPIK learner:** needs exam-oriented vocabulary/grammar (level not differentiated in v1).

Both roles share the same account model and interface; the only difference is which learning path content is shown.

## Functional requirements

1. A user can register with a valid email and password, then log in with those credentials.
2. Invalid registration and login requests show a clear error without exposing sensitive authentication detail or discarding safe form values.
3. On first login, a user selects a learning goal: conversation or TOPIK. This selection determines which learning path they see and can be changed later from account settings.
4. A user can view and progress through a vocabulary/grammar learning path matching their selected goal, item by item.
5. A user can mark a vocabulary/grammar item as learned or not yet learned; this state persists across sessions.
6. A user can upload or capture an image containing Korean text (handwritten or printed).
7. The system extracts editable text from that image (OCR) and displays it for reading practice.
8. A user can trigger AI text-to-speech playback of the extracted text, using a default AI voice.
9. A user can view a summary of their own progress: items learned, items remaining, in their selected path.
10. All user-facing interface text is in Vietnamese.

## Non-goals

No voice cloning (reading text back in the user's own voice), no automatic pronunciation scoring, no free-form two-way conversational chatbot, no TOPIK content above level 4, no mobile client, no password reset, email verification, SSO, or social login in this release.

## Assumptions

- A single account has only one active learning goal at a time; a user does not study both goals simultaneously.
- Learning path content (the actual vocabulary/grammar items) will come from a data source that is not yet selected — see `3.1-product-discovery.md` — and is treated as available once the technical decision is made.

## Non-functional expectations

- Interface fully in Vietnamese, including error messages.
- OCR and TTS are v1's primary technical risks; a clear failure state with retry is required even if underlying accuracy is imperfect.
- Web-only in v1; do not design against anything that would block a future mobile client, but do not build mobile-specific work now.

## Acceptance signal

Main path: register → log in → select goal → progress through learning path items → scan a text image → review extracted text → play AI reading → check progress summary → reload and confirm state persists.

See `3.4-user-stories-acceptance-criteria.md` for detailed user stories, and `3.5-feature-specification.md` for detailed technical behavior.
