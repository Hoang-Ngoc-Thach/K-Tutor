# 3.3 — Requirements Analysis

## Requirement grouping

| Group | Related requirements (from PRD) | Priority |
|---|---|---|
| Auth & goal selection | FR-1, FR-2, FR-3 | High — every other flow depends on this |
| Learning path | FR-4, FR-5 | High — the product's core value |
| Scan & reading practice (OCR + TTS) | FR-6, FR-7, FR-8 | High — K-Tutor's key differentiator vs. generic Korean apps |
| Progress tracking | FR-9 | Medium — supports motivation, not a required flow for the product to "work" |
| Interface language | FR-10 | High — a cross-cutting constraint, not a standalone feature |

## Dependencies between requirements

- FR-4 (view learning path) depends on FR-3 (goal selected) — the path cannot render without a known goal.
- FR-8 (AI playback) depends on FR-7 (extracted text exists) — no audio for an image that hasn't gone through OCR.
- FR-9 (progress) depends on FR-5 (marking items learned) — nothing to aggregate if the user has never marked anything.

## Identified risks

| Risk | Level | Note |
|---|---|---|
| OCR misreads handwritten text | High | Mitigated at the requirement level: extracted text must be editable before playback (see 3.5) |
| No suitable free vocabulary/grammar data source found | Medium | Source not yet chosen — see assumptions in 3.1/3.2; must be decided before Chapter 5 |
| Confusion switching between the two learning goals (conversation/TOPIK) | Low | Assumption already documented: switching goals does not delete the previous goal's progress (see 3.5) |
| 2-person team may be overloaded by Chapters 6–9 (implementation) workload | Medium | Out of scope for Chapter 3, but worth flagging for planning |

## Traceability

Every functional requirement in `3.2-prd.md` traces back to a problem or persona stated in `3.1-product-discovery.md`. No requirement was added at this stage without that basis — any new idea surfaced during analysis was recorded as an assumption or deferred to Chapter 4/5, not added directly as a requirement.
