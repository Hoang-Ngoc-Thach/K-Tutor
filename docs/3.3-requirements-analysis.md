# 3.3 Requirements Analysis

**Status:** Accepted
**Source:** `docs/3.2-prd.md`

## 1. Purpose

This document analyzes the functional requirements defined in the accepted PRD, including their grouping, dependencies, risks, and implementation scope.

The analysis covers **FR-1 to FR-17**.

---

## 2. Requirement Groups

| Group                 | Requirements  | Description                                                  |
| --------------------- | ------------- | ------------------------------------------------------------ |
| Authentication & Goal | FR-1 – FR-3   | Registration, login, and learning goal selection             |
| Learning Path         | FR-4 – FR-5   | Learning path and learned state                              |
| Scan & Reading        | FR-6 – FR-8   | Image input, OCR, and TTS/AI playback                        |
| Progress              | FR-9          | Learning progress                                            |
| Interface             | FR-10         | Interface language                                           |
| Conversation & AI     | FR-11 – FR-13 | Conversation topics, AI sentence feedback, vocabulary review |
| Roles                 | FR-14         | Learner/Admin roles                                          |
| Admin Content         | FR-15         | Vocabulary and grammar management                            |
| Admin Users           | FR-16         | User management                                              |
| Admin Statistics      | FR-17         | Usage statistics                                             |

## 4. Key Risks

| Risk                           | Impact                                    | Mitigation                                          |
| ------------------------------ | ----------------------------------------- | --------------------------------------------------- |
| OCR accuracy                   | Incorrect extracted Korean text           | Allow users to review/edit OCR result               |
| Learning content availability  | Learning path and review may lack data    | Use mock data first; prepare initial dataset        |
| Goal switching                 | Progress may become unclear               | Define goal-switching rules before backend          |
| AI service failure/rate limits | Sentence checking may fail                | Provide loading/error states and retry handling     |
| Vocabulary review rules        | Inconsistent review behavior              | Finalize review rules during backend implementation |
| Statistics definition          | Different interpretations of metrics      | Define production metrics before backend            |
| User locking                   | Unclear behavior during active session    | Finalize session behavior before backend            |
| Team capacity                  | Scope may exceed two-person team capacity | Implement incrementally                             |

---

## 5. Current Implementation Boundary

The current development stage focuses on **UI and mock data**.

### Included

All requirements from **FR-1 to FR-17** should have corresponding UI coverage using mock data where necessary.

### Deferred

The following are not required for the current UI stage:

* Backend API integration
* Database persistence
* Real authentication/authorization
* Real OCR integration
* Real TTS integration
* Real AI/Gemini integration
* Production statistics calculation
* Production user-lock enforcement

These remain part of the overall product scope and will be implemented in later stages.
